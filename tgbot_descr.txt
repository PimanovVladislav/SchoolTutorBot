Руководство по Telegram-боту tutor_bot
======================================

Для кого этот файл
------------------
Это текстовое руководство для начинающего программиста. Цель — разобрать
этот проект от нуля: как вообще устроен любой Telegram-бот, как устроен
именно этот, какой файл за что отвечает, какая функция что делает, какие
аргументы принимает, куда уходит управление после нажатия кнопки.

Схема таблиц БД здесь не дублируется целиком: живое описание колонок и
CREATE TABLE лежит в db_descr.txt. Здесь — как бот с этой базой общается.

Стек: Python 3, aiogram 3, SQLAlchemy 2 async + asyncmy, MySQL utf8mb4,
опционально Redis для FSM. Запуск: python main.py (один процесс на токен).


========================================================================
ЧАСТЬ 1. КАК УСТРОЕН ЛЮБОЙ TELEGRAM-БОТ
========================================================================

1.1. Кто с кем разговаривает
----------------------------
Telegram — это мессенджер. Бот — обычный «пользователь» с особым API.

Три стороны:

  1) Клиент ученика (приложение Telegram на телефоне или Desktop).
  2) Серверы Telegram. Они хранят чаты, кнопки, файлы, очередь апдейтов.
  3) Твой Python-процесс. Он НЕ слушает интернет ученика напрямую.
     Он говорит только с API Telegram.

Цепочка одного нажатия кнопки:

  ученик нажал кнопку
    → Telegram принял жест
    → Telegram положил «апдейт» (update) в очередь бота
    → твой процесс забрал апдейт (polling или webhook)
    → aiogram подобрал хендлер (функцию-обработчик)
    → хендлер решил, что ответить
    → процесс вызывает Bot API: sendMessage / editMessageText / ...
    → Telegram показывает ответ ученику

Важно: бот не «сидит в чате» как человек. Он реагирует на апдейты и
шлёт команды API. Если процесс выключен, кнопки ученика копятся у
Telegram и придут пачкой, когда бот снова запустится (у polling есть
лимит давности).

1.2. Токен
----------
Токен выдаёт @BotFather. Это секрет, которым процесс доказывает, что он
и есть этот бот. Лежит в .env как BOT_TOKEN. Его нельзя коммитить.

Любой HTTP-запрос к API выглядит как:
  https://api.telegram.org/bot<TOKEN>/<method>

aiogram прячет это за объектом Bot.

1.3. Апдейт (Update)
--------------------
Апдейт — JSON-пакет «что-то случилось». В одном апдейте обычно одно из:

  message            — новое сообщение (текст, фото, команда /start)
  edited_message     — ученик отредактировал своё сообщение
  callback_query     — нажата inline-кнопка под сообщением
  pre_checkout_query — Telegram спрашивает: можно ли провести оплату
  successful_payment — оплата прошла
  и другие типы, которые этот бот не обрабатывает

Поле update_id монотонно растёт. По нему Telegram понимает, что уже
доставлено.

1.4. Polling и webhook
----------------------
Два способа получать апдейты.

Polling (этот проект): процесс крутит цикл getUpdates. Просто, удобно
для разработки. Минус: нужен постоянно работающий процесс; два процесса
с одним токеном будут драться за очередь.

Webhook: Telegram сам POST-ит апдейты на твой HTTPS URL. Нужен публичный
сервер. На нагрузке это правильнее, плюс несколько воркеров с общим Redis.

В tutor_bot/main.py вызывается dp.start_polling(bot). Webhook не настроен.

1.5. Bot и Dispatcher (aiogram 3)
---------------------------------
Bot     — клиент API: send_message, delete_message, answer_callback_query.
Dispatcher — маршрутизатор: смотрит на апдейт и ищет хендлер.

Хендлер — async-функция с декоратором вроде:

  @router.message(CommandStart())
  async def cmd_start(message: Message, state: FSMContext, session: AsyncSession):
      ...

aiogram сам подставляет аргументы по имени:

  message / callback / event  — объект из апдейта
  state                       — FSM этого пользователя (см. ниже)
  session                     — мы кладём в data через middleware
  bot                         — кладётся фреймворком
  callback_data               — если фильтр CallbackData.filter()

Если имя аргумента aiogram не знает, будет ошибка. Новые зависимости
добавляют через middleware: data["session"] = session.

1.6. Router и порядок
---------------------
Router — коробка с хендлерами. Их включают в Dispatcher или в другой
Router. Порядок include_router важен: первый подходящий хендлер побеждает.

В этом проекте (tutor_bot/handlers/__init__.py setup_routers):

  1. start         — /start, выбор предмета и класса, /cancel, /class
  2. subscription  — /grant, /revoke, /stats, оплата Stars
  3. student       — главное меню, обучение-список, прогресс, настройки,
                     навигация Назад/На главную, вся проверочная
  4. admin         — админка; на роутере стоит фильтр AdminOnly
  5. learn         — теория, тренировка, подсказка, разбор, ответ на задачу

Почему student раньше learn: кнопки «Назад», «На главную», «Завершить
работу» должны перехватываться student, а не попадать в handle_answer
как «ответ ученика».

Почему admin раньше learn: текст «Отмена» и админ-кнопки не должны
считаться ответом на задачу.

1.7. Фильтры
------------
Хендлер срабатывает, только если все фильтры в декораторе истинны.

Примеры из проекта:

  CommandStart()              — текст сообщения это /start или /start payload
  Command("learn")            — /learn
  F.text == BTN_HOME          — текст в точности «На главную»
  F.text.in_({...})           — текст из множества
  F.text.regexp(r"...")       — текст подходит под регулярку
  ~F.text.startswith("/")     — текст НЕ начинается с /
  ~F.text.in_(NAV_BUTTONS)    — текст не является служебной кнопкой
  StateFilter(Learn.exam_work, Learn.exam_answer)
                              — текущее FSM-состояние одно из двух
  Learn.waiting_answer        — то же, коротко: состояние равно этому
  MenuCB.filter(F.a == "hm")  — нажата inline-кнопка с action hm
  SubjectCB.filter()          — любая inline-кнопка предмета
  AdminOnly()                 — кастомный фильтр: user.id в ADMIN_IDS

F — magic-filter aiogram. F.text значит «поле text апдейта».

1.8. Два вида клавиатур. Это критично
-------------------------------------
Telegram разрешает ОДНУ reply_markup на сообщение. Либо нижняя
клавиатура, либо кнопки под сообщением, не оба сразу.

A) Reply keyboard (обычная клавиатура внизу чата)
   Класс: ReplyKeyboardMarkup, кнопки KeyboardButton.
   Видна постоянно, пока бот не пришлёт другую или ReplyKeyboardRemove.
   Нажатие = обычное текстовое сообщение. Хендлер ловит F.text == "...".
   В этом проекте главное меню, разделы, проверочная, админка — такие.

   Нюанс Telegram Desktop: клавиатура «привязана» к сообщению, с которым
   её прислали. Если это сообщение сразу удалить, меню на Desktop
   мигает и пропадает. Поэтому бот держит «живого владельца»
   клавиатуры (reply_kb_id) и никогда не шлёт пустой символ-заглушку.

B) Inline keyboard (кнопки под конкретным сообщением)
   Класс: InlineKeyboardMarkup, кнопки InlineKeyboardButton.
   Нажатие = callback_query, не сообщение в чат.
   callback_data — короткая строка (лимит Telegram 64 байта).
   В этом проекте: выбор предмета/класса, подсказка/разбор/пропуск
   на карточке задачи, оплата Stars, пагинация учеников в админке.

После обработки callback ОБЯЗАТЕЛЬНО вызвать callback.answer().
Иначе у ученика бесконечные часики на кнопке. Текст в answer() —
короткий тост; show_alert=True — модальное окно.

1.9. Команды и кнопка Menu
--------------------------
BotFather и метод setMyCommands публикуют список /start, /learn...
Тогда в клиенте появляется кнопка Menu со слэш-командами.

Этот бот при старте вызывает bot.delete_my_commands(), чтобы Menu
не показывала /start-/learn-/settings. Действия живут на нижней
клавиатуре. Сами хендлеры Command("learn") и т.п. оставлены: если
человек сам напишет /learn, это сработает.

/start остаётся штатным входом: его можно набрать вручную, он есть
у каждого бота с самого создания.

1.10. FSM (конечный автомат)
----------------------------
«Состояние» пользователя хранится отдельно от хендлеров.

StatesGroup — набор имён состояний (tutor_bot/states.py).
FSMContext — объект, чтобы читать/писать состояние и data.

  await state.set_state(Learn.waiting_answer)
  await state.get_state()            # строка вроде "Learn:waiting_answer"
  await state.update_data(topic_id=5)
  data = await state.get_data()      # dict
  await state.clear()                # стереть состояние и data

Хранилище:
  MemoryStorage — в RAM процесса. Пропал процесс — пропали состояния.
  RedisStorage  — если задан REDIS_URL. Нужен, когда ботов несколько.

Ключ FSM в aiogram по умолчанию: (bot_id, chat_id, user_id).
В личке chat_id == user_id.

Этот бот кладёт в data не только поля формы, но и стек экранов,
id сообщений для удаления, id текущей задачи. Это не «магия FSM»,
это просто dict, который переживёт апдейты.

1.11. HTML в сообщениях
-----------------------
Bot создаётся с ParseMode.HTML. Значит в тексте можно:

  <b>жирный</b>  <i>курсив</i>  <code>моно</code>  <a href="...">ссылка</a>

Любой пользовательский ввод (имя, название темы) нужно экранировать
html.escape, иначе «<» сломает разметку или откроет дыру.

Лимит Telegram на текст сообщения — 4096 символов. В проекте режут
по 3900 (RESULT_LIMIT) и 4000 (THEORY_LIMIT), с запасом.

1.12. Идентификаторы
--------------------
user.id / from_user.id — Telegram id человека. В users.id хранится он же,
не автоинкремент. Это важно: send_message(target.id) шлёт в личку.

message_id — номер сообщения в чате. Удаление и правка идут по паре
(chat_id, message_id).

callback_data — не путать с id. Это наша короткая строка на кнопке.


========================================================================
ЧАСТЬ 2. ЧТО ЭТО ЗА БОТ И КАК УЧЕНИК ПО НЕМУ ИДЁТ
========================================================================

Продукт: репетитор в Telegram. Сейчас контент — школьная математика
6–9 классов. Ядро рассчитано на несколько предметов и треков (школа,
ОГЭ, ЕГЭ) без нового бота.

Путь ученика:

  /start
    нет класса/предмета → онбординг (inline: предмет, потом класс)
    есть               → приветствие + ГЛАВНОЕ МЕНЮ (reply)

  Главное меню (только здесь эти три кнопки):
    «Продолжить обучение» → список несданных тем + «Начать с N»
    «Мой прогресс»        → сданные на 3+ темы, номер или «и1» для истории
    «Настройки»           → класс/предмет, подписка, обращение, расписание
    «Админка»             → только если user_id в ADMIN_IDS

  Тема:
    теория (можно ещё одну редакцию) → тренировка → проверочная

  Тренировка:
    задача с inline: Подсказка / Разбор / Пропуск / жалоба
    после верного ответа снизу: Решить ещё, уровни, К проверочной

  Проверочная:
    снизу список заданий «N · Нет ответа» / «N · ответ отправлен»
    плюс Завершить работу, Назад, На главную
    ответы копятся, оценка ставится только при завершении или истечении
    срока (ASSESSMENT_HOURS, по умолчанию 24 часа)

  Результат:
    снизу «N · верно/неверно/нет ответа» — раскрывает разбор задания

На любом экране кроме дома: Назад (снять текущий экран, вернуть
предыдущий) и На главную (стереть UI, показать HOME_TEXT).

========================================================================
ЧАСТЬ 4. КОНФИГ И ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ
========================================================================

Файл tutor_bot/config.py читает .env через python-dotenv (load_dotenv).

Вспомогательные функции
-----------------------
_int_env(name, default)
  Берёт os.getenv(name). Пусто или нет ключа → default.
  Иначе int(...). Нужна, чтобы TRIAL_DAYS="3" стало числом.

_admin_ids()
  Читает ADMIN_IDS — строка через запятую, например "111,222".
  Возвращает frozenset[int]. Пустая строка → пустое множество.
  Человек из этого множества видит кнопку «Админка» и проходит AdminOnly.

Константы
---------
PROJECT_ROOT
  Path к корню репозитория (родитель tutor_bot/). Нужен, чтобы
  media/... резолвились одинаково, откуда бы ни запустили процесс.

BOT_TOKEN
  Токен BotFather. Пустой → main() бросает RuntimeError.

DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME
  Подключение к MySQL. Порт по умолчанию 3306, база tutor_bot.

DATABASE_URL
  Собирается сам: mysql+asyncmy://user:pass@host:port/name?charset=utf8mb4
  Пароль прогоняется через quote_plus, чтобы спецсимволы не ломали URL.

ADMIN_IDS
  frozenset Telegram id админов.

TRIAL_DAYS (int, default 3)
  Сколько суток после users.created_at можно заниматься без подписки.
  0 — триала нет.

STARS_PRICE (int, default 0)
  Цена 30 дней в Telegram Stars. 0 — кнопка оплаты не показывается,
  доступ выдаёт админ командой /grant или кнопкой в админке.

REDIS_URL (str | None)
  Если задан — FSM в Redis. Если нет — MemoryStorage.
  Для двух процессов с одним токеном Redis обязателен, иначе состояния
  каждого процесса свои, и ученик «ломается».

WRONG_ATTEMPTS_BEFORE_HELP (default 2)
  После скольких неверных ответов на тренировке появляется
  «Помощь · разбор».

TRAINING_REPEAT_DAYS (default 7)
  Кулдаун: недавно решённую тренировочную задачу не давать снова.

ASSESSMENT_HOURS (default 24)
  Срок проверочной от started_at до deadline_at.

POOL_SIZE (DB_POOL_SIZE, default 20)
POOL_MAX_OVERFLOW (DB_POOL_MAX_OVERFLOW, default 40)
  Пул соединений SQLAlchemy. На много учеников увеличивать вместе
  с лимитами MySQL.


========================================================================
ЧАСТЬ 5. ЗАПУСК ПРОЦЕССА (tutor_bot/main.py)
========================================================================

Цепочка python main.py:

  1) asyncio.run(main())
  2) Если BOT_TOKEN пуст — падение с понятной ошибкой.
  3) _init_db():
       engine.begin() → apply_schema (таблицы + ALTER)
       session_factory() → seed_curriculum (математика 6–9)
       commit
  4) Bot(token, default parse_mode=HTML)
  5) Dispatcher(storage=_storage())
       Redis, если REDIS_URL, иначе память
  6) dp.error.register(on_error)
  7) dp.update.middleware(DbSessionMiddleware)  — на КАЖДЫЙ апдейт
  8) dp.message.middleware(TypingMiddleware)
     dp.callback_query.middleware(TypingMiddleware)
     (на pre_checkout typing не вешается — там нет «печатает»)
  9) dp.include_router(setup_routers())
 10) bot.delete_my_commands()  — спрятать Menu со слэш-командами
 11) notify_admins("Бот запущен")

6.1. DbSessionMiddleware (middlewares/db.py)
-------------------------------------------
__init__(self, session_factory)
  Запоминает фабрику сессий.

__call__(self, handler, event, data)
  Открывает async with session_factory() as session:
    data["session"] = session
    result = await handler(...)
    await session.commit()
    return result

Следствия:
  - каждый хендлер может объявить session: AsyncSession
  - commit автоматический, если хендлер не упал
  - если хендлер бросил исключение, commit не будет (сессия закроется
    с rollback по контекстному менеджеру)
  - не держи сессию дольше одного апдейта и не клади объекты ORM
    в FSM data: после закрытия сессии они expire

6.2. TypingMiddleware (middlewares/typing.py)
--------------------------------------------
Пока хендлер думает, шлёт chat action typing (через 0.25 с).
Если bot или chat_id не найдены — просто вызывает handler.

_chat_id(event)
  Message → event.chat.id
  CallbackQuery с message → message.chat.id
  иначе None (например, pre_checkout)

ЧАСТЬ 9. НАВИГАЦИЯ И «ВЛАДЕЛЕЦ» КЛАВИАТУРЫ (services/nav.py)

Идея стека как у мобильного приложения. В FSM data ключ "nav" —
список экранов. Каждый экран: словарь {s, ..., ids}.

  s     тип: home, learn, progress, settings, theory, training,
        exam_info, exam_work, exam_result, history, subjects, grades, stub
  t     id темы, если нужен
  a     id попытки проверочной
  i     номер заглушки настроек
  ids   message_id, которые принадлежат ЭТОМУ экрану (их сотрёт Назад)

HOME_TEXT = "Главное меню. Выберите действие:"

Функции
-------
screen_key(screen)
  Копия без ids. Нужна, чтобы не считать «тот же экран» другим из-за
  новых сообщений.

get_stack(state) / set_stack(state, screens)
  Прочитать / записать nav.

reset_stack(state, screen)
  Стек из одного экрана. Так входят в «Продолжить обучение», «Прогресс»,
  «Настройки»: Назад с них ведёт домой (длина стека 1).

goto(state, screen)
  Кладёт экран наверх, если его ключ не совпадает с текущим верхом.
  Так теория поверх списка тем, проверочная поверх теории.

replace_top(state, screen) → старый верх или None
  Снять верх и положить новый. Используется, когда «Приступить»
  превращает exam_info в exam_work: карточка правил больше не нужна
  в стеке.

pop_screen(state) → снятый экран или None
  Назад: сначала pop, потом удалить его ids.

track_ui(state, ids)
  Глобальный список ui_ids — все сообщения бота, которые На главную
  должна уметь стереть, даже если стек уже потерял ссылку.

attach_ids(state, ids)
  Дописать ids к текущему верху стека И в ui_ids. Вызывать после
  каждой отправки «экранного» сообщения.

collect_ui_ids(state)
  Собирает id из ui_ids, theory_*, ephemeral_*, exam_*, reply_kb_id,
  всех screen["ids"]. Без дублей. Для полной зачистки.

wipe_ui(bot, chat_id, state, extra=None)
  Удаляет все собранные id (+ extra, обычно message_id нажатой кнопки)
  и обнуляет навигационные поля data. Вызывается из «На главную»,
  /start, входа в обучение/прогресс/настройки.

forget_reply_kb_if_deleted(state, deleted_ids)
  Если среди удалённых был владелец клавиатуры — reply_kb_id = None.
  Иначе Telegram Desktop потеряет меню, а бот будет думать, что оно живо.

set_reply_kb_owner(state, message_id)
  Запомнить, какое сообщение «держит» нижнюю клавиатуру.

adopt_reply_kb(bot, chat_id, state, message_id)
  Новое сообщение стало владельцем.
  reply_kb_stub=False (это контент, не фраза «Выбери действие:»).
  Если СТАРЫЙ владелец был заглушкой (stub) — удалить его, чтобы не
  копились пустые/короткие сервисные сообщения.
  Контент (теория, список тем) НЕ удаляется.

apply_reply_keyboard(target, state, markup, *, force=False,
                     caption="Выбери действие:")
  Когда клавиатуру надо показать, а прикрутить её к старому сообщению
  через edit нельзя (edit меняет только inline).
  Если владелец уже есть и force=False — ничего не делать.
  Иначе отправить caption с markup, пометить stub=True, старую заглушку
  удалить.
  caption никогда не должен быть пустым или невидимым символом:
  на Desktop пустое сообщение «висит», а клавиатура к нему привязана.

Нюанс Desktop ещё раз: после «Завершить работу» результат сам несёт
exam_result_reply_keyboard (adopt на это сообщение). apply_reply_keyboard
после экзамена НЕ вызывается — иначе появилось бы лишнее сообщение.

ЧАСТЬ 15. ГЛАВНОЕ МЕНЮ И УЧЕНИК (handlers/student.py)

15.1. Константы
---------------
STUBS = {1: подписка, 2: обращение, 3: расписание} — тексты «скоро».
RESULT_LIMIT = 3900 — обрезка раскрытого результата.

15.2. Показ экрана
------------------
_present(target, state, text, markup=None, *, edit=False, user_id=None)
  Единая отправка «экрана».
  edit=True: правит текст; inline можно передать, reply через edit
             не ставится (ограничение API).
  markup InlineKeyboardMarkup: отправить с inline, НЕ менять владельца
             нижней клавиатуры (пример: выбор предмета из настроек —
             снизу остаются Назад/Настройки).
  markup ReplyKeyboardMarkup или None: None → section_for (Назад/Домой).
             Сообщение становится владельцем клавиатуры через adopt.

_safe_edit(target, text, markup)
  edit_text, при неудаче — новое send_message.

15.3. Клавиатуры разделов при «Назад»
-------------------------------------
_section_kb_for(state, user_id, screen)
  По screen["s"] собирает правильную нижнюю клавиатуру.
  exam_work → None (панель экзамена сама держит клавиатуру).
  exam_result → простой section_for, если нужно восстановить после
  вложенного экрана.

_restore_section_reply(target, state, user_id, screen, *, force=False)
  Если kb не None — apply_reply_keyboard с человеческой подписью
  («Теория. Выбери действие:» и т.д.). force=True, когда предыдущий
  владелец удалён (ушли с экзамена, стёрли теорию).

15.4. Вход с главного меню
--------------------------
btn_learn  — текст BTN_CONTINUE или Command("learn")
btn_progress — BTN_PROGRESS / /progress
btn_settings — BTN_SETTINGS / /settings

Общий рисунок: wipe_ui (включая нажатую кнопку), проверка
_require_student (класс выбран? доступ есть?), затем
show_learn_list / show_progress_list / show_settings.

_require_student(session, tg_user, target) → (user, error)
  error: None | "choose" | "denied"
  denied уже отправил текст отказа с menu_for.

show_learn_list(...)

  Темы класса, у которых best_grade ещё не 3+.

  В data: start_topic_id, start_number, pick_source="learn".

show_progress_list(...)

show_settings(...)

15.5. Выбор темы
----------------
start_from_button — regexp «Начать с N» в состоянии pick_topic.

  иначе тему по номеру. Удаляет пузырь нажатия. _open_theory.

  «иN» → _show_history (список попыток текстом).
  число → _open_theory.

_open_theory(target, state, session, user, topic_id)
  Если верх стека уже theory — заменить (переход с темы на тему),
  иначе goto theory. Дальше learn.show_topic_theory.

15.6. Назад и домой
-------------------
_navigate_home(target, state, user_id)
  wipe_ui, state None, сообщение HOME_TEXT + menu_for, стек {s: home}.

_navigate_back(...)
  Если состояние exam_answer и открыт вопрос — только закрыть вопрос,
  остаться в exam_work (клавиатура экзамена жива).
  Если стек длины 1 — домой.
  Иначе pop, _discard_screen (удалить ids текущего), восстановить
  состояние предыдущего через _apply_screen_state.
  force_menu, если reply_kb_id стал None (владельца стёрли).

_discard_screen(...)
  exam_work: стереть вопрос и панель, очистить panel_message_id в БД.
  training/theory: стереть ephemeral/theory ids.

_apply_screen_state(...)
  Выставляет FSM (pick_topic / waiting_answer / exam_work / ...)
  и просит _restore_section_reply.

Хендлеры: home_text / back_text (reply-кнопки) и go_home / go_back
(старые inline MenuCB hm/bk).

15.7. Проверочная
-----------------
_show_exam_info

_show_exam_work

  attempt.panel_message_id и exam_panel_ids.
  Состояние exam_work.

  parse_exam_task_button → _open_exam_question.

_open_exam_question

  результат.
  Иначе стереть предыдущий вопрос, состояние exam_answer, send_rich

ЧАСТЬ 23. ТОНКОСТИ И ЛОВУШКИ
========================================================================

1. Один процесс на один BOT_TOKEN при polling. Второй экземпляр
   украдёт апдейты. Несколько воркеров — только webhook + Redis.

2. commit после хендлера. Если нужно гарантировать запись ДО
   внешней отправки (invoice), полагайся на то, что падение после
   commit не откатится — сейчас commit в конце. Критичные вещи
   (оплата) пишутся в том же хендлере до answer.

3. Не клади ORM-объекты в FSM: сессия закроется.

4. callback.answer() всегда. Иначе вечная загрузка кнопки.

5. edit_message_text не меняет reply keyboard. Только inline.
   Смена нижней клавиатуры = новое сообщение с reply_markup.

6. Удаление владельца клавиатуры на Desktop = исчезновение меню.
   Сначала новое сообщение с клавиатурой, потом удалять старое,
   и то только если это stub.

7. Никогда не слать сообщение из одного пробела / U+2063 «чтобы
   прикрепить клавиатуру». Это и есть баг пустого пузыря после
   проверочной, который уже закрыт.

8. Личка: chat.id == user.id. В группах этот бот не рассчитан
   (клавиатуры, wipe, ensure_user).

9. HTML parse mode: сырой «1 < 2» сломает сообщение. escape.

10. Оценка проверочной не живая: пока не нажали «Завершить» или
    не вышел срок, is_correct в строках ответа может быть пустым.
    Кнопки показывают только «отправлен / нет».

11. 5+ требует три максимальных результата подряд (count_max_scores).
    Это не «три любые пятёрки за жизнь».

12. Случайный набор проверочной: при новой попытке старается не
    повторить problem_ids предыдущей. Банк должен быть больше
    assessment_required, иначе повтор неизбежен.

13. Сид перезаписывает задачи тем из math_school.py. Админские темы
    с другим slug в безопасности. Правки «тех же» slug через админку
    могут откатиться при рестарте бота.

14. MemoryStorage + рестарт бота = ученик «выпал» из состояния,
    но сообщения в чате остались. /start лечит.

15. NAV_BUTTONS нужно пополнять при новой нижней кнопке, иначе
    handle_answer примет её за решение.

16. Порядок роутеров — часть контракта. Новый хендлер «любой текст»
    на student.router перехватит ответы тренировки, если его
    поставить без фильтров состояния.

17. Тесты не ходят в Telegram. Они проверяют клавиатуры, дроби,
    пороги оценок. Живой UX проверяй руками в Desktop и на телефоне:
    клавиатуры ведут себя по-разному.

18. notify_admins шлёт «Бот запущен» каждому из ADMIN_IDS. Если id
    неверный или человек не нажал /start боту — Telegram ответит
    ошибкой, она глотается.
